# RRT柔術AIの技術データと運用

[教材分析](../docs/materials-review.md)、[ポジション別フロー](../docs/technique-flows.md)、[品質検証](../docs/quality.md)、[作業の再開](../docs/knowledge-progress.md)

| ファイル | 内容 |
| --- | --- |
| [techniques.json](techniques.json) | 技術ID、和英の技名と別名、開始と役割、姿勢、グリップ、力学、成立条件、動作、反応、失敗と修正、指導、注意、出典と確認範囲、関連技、対応動画 |
| [sources.json](sources.json) | 出典URL、公開／目次／会員の確認範囲と取り扱い |
| [動画台帳](../data/public_videos.json) | 無料公開YouTubeの動画ID、表題、講師、役割、適用できる反応。メタデータだけの候補も保持 |
| [coach.cjs](../lib/coach.cjs) | 日英の質問語、開始位置と上下、相手の反応による検索。Geminiの選択を検査して登録済みの文から回答を構成 |
| [元の独自技術](original_bjj_coaching.json)・[元の分析メモ](editorial_reading_notes.json) | v13から移行した原資料。新データ内で `legacy_ids` に接続 |

`source_refs` は検証・出典確認用。外部原文・動画への利用許諾は出典台帳の権利欄で確認する。PDFのページ番号は `PDF内` の表示。技術の本文は独立して書かれた試用メモで、専門指導者の実技レビューは未実施。外部素材の本文はGeminiの入力に含めない。

決まった反応が一つならサーバーの登録文で返す。複数候補が残るときにだけGeminiへ、その技術の短い助言と次の選択肢、現在の質問、明示的に前の質問を参照した場合の短い文脈を送る。Geminiの応答は登録IDで検査する。モデルが利用不能、選択不能、または上限到達なら登録済みの説明へ戻る。通常は150〜250字を目安とし、詳細指定では手順と分岐を見せる。

| 比較項目 | Node.jsの登録データ検索 | Gemini File Search |
| --- | --- | --- |
| 費用 | 検索のための外部APIや埋め込み料金なし。Geminiの選択には既存プロジェクトの利用枠を使う | Google側の索引化に埋め込み料金。検索時の埋め込みは無料。回答のトークンはモデル料金に従う |
| 精度 | 技名の同義語、上下、反応、動画対応を明示できる。新しい言い換えは検証して追加する | 大量の文章を意味で探すのに適する。上下の制約と教材別の権利は別途フィルタリングが必要 |
| 利用条件・個人情報 | 技術台帳をRenderのみで検索。許可された独自説明と必要な質問だけを既存APIへ送信 | 文書の外部送信と保存を伴うため、収録する素材の許諾と削除管理が必要 |
| 実装 | 既存Node.jsとJSON、追加インフラなし | ストアの作成・索引化・差替え・権限を運用 |
| 判定 | 今回採用 | 現時点では導入対象外 |

[Google File Search](https://ai.google.dev/gemini-api/docs/file-search)、[Gemini価格](https://ai.google.dev/gemini-api/docs/pricing)、[Gemini追加利用規約](https://ai.google.dev/gemini-api/terms)

日本で使う試用アプリでは、無償サービスの入力と出力が製品改善や人によるレビューに用いられる可能性がある。会員の連絡先、個人を特定する内容、非公開の教材本文、専用リンクは質問に含めない。サーバーは明示的なメール・電話・専用リンク等のパターンを見つけたら選択リクエストを送らない。この検出で個人情報一般を網羅することはできない。質問や回答をアプリのログへ書く処理は追加していない。

従来のモデル設定・サーバー側の認証を利用する。登録文で完結する質問では呼び出し0、モデル選択のある質問では最大1回で自動リトライしない。最大出力は400トークン。アプリの既定上限はUTC日付で全体100、セッション20、毎分8。再起動やセッション再発行で状態が変わるため、Googleプロジェクトの上限として使わない。実効上限はAI Studioで確認する。[レート制限](https://ai.google.dev/gemini-api/docs/rate-limits)

データ追加時は `technique.template.json` と同じ形を使い、既存IDを維持する。動画は発行元または講師の本文で動画の内容を確認し、実在ID・役割・技・必要なら反応を双方向で登録する。本文で分からない動画はメタデータ状態のまま。再生時刻が確認できていなければ空欄にする。変更後は `npm run validate:knowledge` と `npm test` を実行する。
